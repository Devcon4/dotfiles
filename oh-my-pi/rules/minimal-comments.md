---
description: "Comments are context tax. The default is zero; only a closed list is allowed"
alwaysApply: true
---

Comments compete with code for agent context. The default is **none**. A comment is a
defect unless it is on this closed list:

1. **Markers the toolchain reads.** These are code. Never strip, never reflow. Examples:
   `//go:build`, `+kubebuilder:` / `+optional` / `+k8s:`, `#pragma`,
   `// <auto-generated>`, a lint suppression that names its rule.
2. **Doc text a tool publishes to a user.** CRD field docs become `kubectl explain` text,
   OpenAPI descriptions become API reference, CLI help becomes `--help`. Write for that
   user: what the field does, its default, what an invalid value causes. The one place
   multi-line is allowed. Inspector-facing text in Unity belongs in `[Tooltip("...")]`,
   which is an attribute, not a comment.
3. **A one-line WHY for code that looks wrong but isn't.** A race, an API or engine quirk,
   an ordering the reader would "fix" and break. One line. Says WHY, never WHAT. If the
   WHY needs a second line, the code is too clever: restructure, or move the rationale to
   an ADR under `docs/adr/` and reference it by number.
4. **API docs on exported or public identifiers**, in the language's own doc format
   (godoc, C# `///` XML docs, TSDoc). Allowed where a caller needs the contract, never
   required on every public member. Strict contract only: inputs, result, error cases,
   null/zero behavior, in one sentence or at most a short paragraph. Never rationale,
   history, implementation notes, or a restated name (`// NewFoo returns a new Foo`).

Everything else is prohibited. Concretely never write:

- narration or restatement (`// loop over realms`, `// Step 3`, `// click save`)
- section banners, file headers, template scaffold prose (`// Add your logic here`,
  `// TODO(user): ...`). Strip these on first contact
- `TODO` / `FIXME` / `XXX`. Unfinished work goes in the scratch `tasks` doc or the
  project's tracker, not the code
- commented-out code
- comments in tests. The test name and the assertion are the documentation
- anything session-scoped: timings ("~35s"), dates, agent/tool/session references,
  "currently" / "for now" / "recently" / "temporary"
- multi-line rationale outside case 2

Decision test: could the comment be deleted by renaming a symbol, extracting a function,
or making the type say it? Then do that instead. When editing existing code, delete every
comment that fails this list, including ones you did not write.

A repo can narrow or extend this list with its own `.omp/rules/minimal-comments.md`, which
replaces this one for that repo.
